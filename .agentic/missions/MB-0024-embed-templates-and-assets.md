## Context

Found in the deployment assessment (2026-11-08). `templates::build_registry`
reads `./templates` and `main.rs` serves `Files::new("/assets", "./assets")`,
both relative to the working directory. A release binary started from
anywhere else fails at startup (templates) or serves 404s (assets). MB-0022's
Docker image works around this by copying both folders. This brief removes
the need, which also keeps the binary and its templates from drifting apart
on a manual deploy.

`main.rs` is a security trigger path for its session middleware. This change
touches only the `/assets` registration, which MB-0018's P4 guard pins first
in `main.rs`. The PR still needs CODEOWNERS review.

## Conceptual plan

- Generate the embedded file lists at build time, re-run when the folders
  change, and register templates from memory with the same names.
- Serve `/assets/{path}` from the embedded map with a GET/HEAD handler and
  `mime_guess`-equivalent content types (escalate if that needs a crate),
  registered where `Files` is today.
- Keep the test-time registry path (`CARGO_MANIFEST_DIR`) only if it still
  earns its place.

Slow-mode trigger: MB-0018's coverage guard fails on the new `/assets`
registration.

## Validation plan

- P1–P4 as unit and route tests at the named paths.
- Smoke: `cargo build --release`, copy the binary alone to a temp directory
  with a `.env`, run it, curl a page and `/assets/app.css`.
