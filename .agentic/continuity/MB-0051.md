## Decisions and constraints

- Decision: popover dropdown in the top bar, `aria-current="true"` and a decorative check mark, no ARIA menu roles, flag-icons 7.6.0 with `gb` for English, `assets/flags/<tag>.svg` as `image/svg+xml`, content and checksum tests. Resolution Record: RR-0031.
- Decided within the brief's `may_decide`:
  - the opener's accessible name is an `aria-label` from one whole-sentence key, `language.current` ("Language: English", "Kieli: Suomi"), not a hidden prefix joined to the visible name (templating.md: one key per sentence). The name follows a colon, so Finnish inflects nothing;
  - the selector comes after the `<nav>` in the HTML, so the keyboard and reading order match what wide screens show; on phones only the visual order changes (the menu button is tabbed to before the selector, though it is drawn after it);
  - breakpoint: MB-0040's 40rem. Class names `lang`, `lang-open`, `lang-menu`, `lang-short`, `lang-full`, `lang-chevron`, `lang-check`, `flag`;
  - `.brand` gets `margin-right: auto`, so the selector and the menu button sit together at the right on phones instead of the selector floating in the middle;
  - flags are drawn at 20 by 15 px with a 1 px outline (a box shadow in `app.css`), so Finland's white flag shows on a white bar;
  - the list (`<form>`) keeps `aria-label` "Language" / "Kieli" (`language.label`), as the footer form had.
- Test changes outside the new tests, covered by RR-0031 ("narrowing MB-0040's `panel()` helper"): `panel()` counts only openers that target a `<nav>`; `navigation_panel`'s two `aria-current` assertions now look for `aria-current="page"`, since the selector uses `aria-current="true"`; `serves_every_asset` also fails on a `SERVED_AS` row without a file.
- Constraint discovered: an author `display` on a popover overrides the browser's "hidden until open" rule, so `.lang-menu:not(:popover-open) { display: none; }` is needed (as for `.site-nav`).
- Constraint (RR-0031): flags are inert and pinned; no script for the dropdown; one form, one endpoint.
