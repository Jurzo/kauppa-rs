## Decisions and constraints

- RR-0032 governs. Its constraints: every action pinned by SHA with a version comment, a new `write` permission on the allowlist needs an RR; one Rust version in the file and the image, changed together; bot PRs merge only inside the four classes and conditions, each with the owner's approval, never auto-merge; `edited` stays on `agentic-gate.yml`; the standing approval is reviewed quarterly with the `deny.toml` prune (next: February 2027).
- Decided inside the brief's `may_decide`:
  - `check_workflows.sh` accepts a version comment of the form `# v<digits>[.<digits>…]`; local `./` actions are exempt; `docker://` actions fail; the allowlist is `(deploy.yml, image, packages)`. It also compares the number of `uses` keys in the parsed YAML with the lines it read, so a `uses` written another way can't slip past.
  - Toolchain names it looks for in workflows: `toolchain:`/`rust-version:`/`RUSTUP_TOOLCHAIN` values, `+<name>`, `rustup … install/default/override set/run <name>`, `rust-toolchain@<name>`. The file's own version is allowed.
  - **`ARG` → `FROM`.** Moved. Dependabot's Dockerfile parser matches only lines that start with `FROM` and an image name; `FROM ${RUST_IMAGE}` doesn't match.
  - **Compose.** The `docker-compose` ecosystem is used for `deploy/compose.yaml`: its file pattern matches `compose.yaml` and its parser reads Caddy's tag and digest. `kauppa-backup:local` is ignored by name.
  - **Dependabot layout:** five entries, one group each (`cargo`, `actions`, `images`, `compose-images`; the toolchain entry has one dependency), `open-pull-requests-limit: 1` each (five in total), `cooldown.default-days: 7` on all five (the options reference lists `default-days` for every ecosystem; it doesn't apply to security updates), cargo and actions and toolchain weekly on Monday, images monthly, label `dependencies`.
  - cargo proposes direct dependencies only (Dependabot's default). `allow: dependency-type: all` would add transitive ones; left for S3.
  - Actions are one group, majors included (RR-0032: "actions weekly (one PR)"). If the first PR, with seven major upgrades, is too much to review at once, split majors out in S3.
  - `deny.toml`: the `getrandom` comment is one sentence with `rand_core`'s; both halves were rewritten from the tree (the old text said proptest's chacha20 pulls both `rand_core` versions; 0.6 comes from password-hash and rand 0.8).
- Side effect on this machine: running `rustup toolchain install` to test the CI step installed the `1.99.1` toolchain and let rustup update itself from 1.29.2 to 1.29.3. The CI step has `--no-self-update`.
