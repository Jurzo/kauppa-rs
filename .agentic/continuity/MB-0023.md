## Decisions and constraints

- `may_decide` (default expiry): 7 days, `domain::invitation::INVITATION_TTL_DAYS`.
- `may_decide` (portal layout): one page, `templates/admin/invitations.hbs`, reusing the list styles (`add-product`, `product-list`) plus a few `.invite-*` rules in `assets/app.css`; plain forms and 303s, so no htmx is needed; no "Admin" link in the layout (it would need an admin lookup on every page). Login and home pages say accounts are by invitation instead of linking to sign-up.
- `may_decide` (test placement): `routes::auth::tests::{register_requires_invite, request_log}`, `routes::admin::tests::{access, invites}`, `admin::bootstrap::tests` (inline), `repo::invite` (P2 tests grouped in a `single_use_and_expiry` module), `csrf::tests::cross_site::invite_routes_reject_only_on_proof`.
- Other choices inside RR-0012: creating an invitation answers 200 with the page (not a 303: the token can't go in a redirect URL) and sends `Cache-Control: no-store` and `Referrer-Policy: no-referrer` like the register page; register responses carry both headers on every path, extractor errors included; `http.client_ip` stays as before in the new root span (MB-0026 replaces it); the admin grant's "no account" case logs at INFO without the email.
- Implementation choices inside RR-0012 (no escalation needed): only a pending invitation can be revoked (used, revoked, expired and unknown ids are all `NotFound` → 404); notes are trimmed and capped at 200 characters in core (`Invalid`); a token is well-formed only as 64 *lower-case* hex characters (what the generator emits); a new `CoreError::Random` variant carries an OS RNG failure (500) instead of a panic.
- CRP-0013 (MB-0026, drafted on branch `agentic/mb-0026-rate-limit`) covers the register rate limit that bounds invitation-token guessing and the duplicate-email oracle (CRP-0012 Q4, Q7).
- MB-0022's order (2026-11-08): MB-0023, MB-0025 and MB-0026 before public DNS points at the droplet; MB-0024 and MB-0027 can land before or after.
