## Decisions and constraints

- RR-0033 (approved): one route, old routes removed; `update_item` in one transaction behind the predicate; old repo methods kept for MB-0048; grantee with a category → 403, nothing changes; blank `category_id` = not sent; malformed id → "unknown category" (parsed before access, as before); the picker not required in this form; `common.set` removed; Save last, Remove below.
- RR-0033 constraint 4: restoring a separate category or quantity route needs an RR.
- Implementation choices inside the brief's `may_decide`:
  - The picker option is a `required` field on `Picker` (`Picker::optional` for list items) rather than a hash parameter on the partial, so strict-mode rendering never meets a missing field on the favorites and recipe pages.
  - The "create a category" hint for an owner without categories stays above the form.
  - `update_item` writes the quantity first, then the category; the order makes no difference to the result since both are in one transaction and any error rolls back.
- Existing tests changed only where they posted to a removed route or asserted its form (CRP-0033 Q6): `lists/tests/items.rs` (`owner_isolation`, `htmx_fragments`, `edit_quantity`), `lists/tests/mod.rs` (`list_posts`' `"category"` entry now posts the new route with a category), `lists/tests/sharing_roles.rs` (the editor's "no category control" check is now `name="category_id"`; `quantity_follows_roles` uses the new route). In `htmx_fragments` the blank-category rejection became a malformed id ("unknown category"), since blank now saves the quantity only (covered in `item_edit`).
- For MB-0048: after this mission `assign_category` and `set_item_quantity` have no production caller, and `repo/sqlite/list.rs` is 855 lines.
