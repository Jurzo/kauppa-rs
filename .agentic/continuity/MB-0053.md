## Dead ends and rejected approaches

- A later `.add-product select, .product-edit select` rule for the
  chevron only: it would depend on each select's ancestors (the category
  picker is a partial used in four places), which a static test can't
  follow. A bare `select` rule matches all of them by construction.
- A bare `select` rule next to the old shared rule: lower specificity
  than `.add-product select`, whose `background` shorthand resets
  `background-image`.
- `data:` SVG background: forbidden by RR-0019 and the brief.
- SVG file under `assets/`: needs a consult, and can't follow the theme
  colour from a background image.
- `select::-ms-expand`: only old IE and EdgeHTML, which the app's
  `popover`-based navigation doesn't target anyway; left out.

## Decisions and constraints

- CSS-only chevron with gradients (`may_decide`); colour `var(--muted)`,
  as MB-0051's language chevron.
- Sizes (`may_decide`): chevron 0.75rem x 0.375rem, 0.875rem from the
  edge, right padding 2.25rem.
- `-webkit-appearance` and `-moz-appearance` are kept next to
  `appearance` for older Safari and Firefox.
- No `outline` declaration on selects, so the browser's focus ring stays
  (the test checks it).
- Test name as the brief has it: `templates::tests::select_chevron`; no
  rename.
- Constraint: RR-0019 (`img-src 'self'`, `style-src 'self'`); the
  policy is unchanged.
